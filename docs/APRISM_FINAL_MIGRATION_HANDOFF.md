## Architecture and protected domain model

- Stack: PHP `^8.2`, Apache/XAMPP local runtime, MySQL/MariaDB through PDO, Bootstrap 5, Vanilla JS/CSS, Composer `phpoffice/phpspreadsheet` `^5.9`, and locally packaged browser OCR assets. `composer.json`, `composer.lock`, `vendor/`, `assets/vendor/`, `config/pdo.php`, and `database/migrate.php` are part of the technical baseline.
- Route shape: `dashboard/` renders role pages; `actions/` owns mutations; `includes/helper/` holds shared domain logic; `auth/` enforces session/authorization; `assets/` owns styling and browser behavior; `database/*.sql` plus ordered `database/migrations/*.sql` evolve local schema. `schema_migrations` is the local ledger. Do not run `database/migrate.php` on another database before checking its current schema and ledger.
- Roles: Technical Administrator, Academic Head, Teacher, Disciplinary Officer (`ROLE_DISCIPLINARY_OFFICER`). Adviser is a scoped Teacher responsibility, never another login role. Program Head is deferred. Technical Admin manages accounts/capability/handover; Academic Head manages relevant academic context, placement exceptions, and Adviser assignment under existing permissions.
- One active School Year is explicitly selected by Academic Head. Teaching context/semester is broader than Academic Period. `student_id` is permanent identity; Student Number is the authoritative external import key where available. Name-only Class List rows have a tightly scoped unresolved-participant review path; they never justify a global name merge. SAE is historical academic placement; SCE is actual Operational Class participation. Missing SAE does not block valid SCE, Attendance, Grades, Referrals, or Teacher My Students. Adviser Student scope is Section/SAE based. The confirmed Section-name convention may **propose Section metadata during controlled, reviewed setup**; never infer a Student's placement or historical context from a label, or create placement to satisfy a test.
- AprilTag family is `tagStandard52h13`, usable IDs `0–48713`. Current ownership is global and persistent; term context is provenance. Offline scans queue in IndexedDB and become recorded only after server validation. The current scanner explicitly does not support reopening the page while offline; a queue already saved on a device must not be described as server-recorded. Attendance grace, absence, and pre-start values are Technical Admin configurable; do not hard-code historical examples. Preserve 3 lates = 1 effective absence and FDA only with an authoritative total-hours denominator.
- Grade Import stores raw assessment scores and revisions; review and explicit confirmation precede persistence. Do not invent a grade formula. Risk tiers come from the existing evaluator; snapshots remain historical. Referrals and disciplinary cases retain original actor/Student scope and required audit. Class Handover changes current `operational_classes.teacher_id`, not Student, roster, schedule, grade, referral, or original author IDs. Future Attendance Sessions record their actual conductor; unknown legacy conductors remain unknown.
- Security: server-side role/ownership authorization, CSRF, required audit where established, transaction rollback, one active session, session regeneration, lockout, forced password change, and configurable session timeout. Do not weaken these to make QA easier. UI follows `DESIGN.md` and “Fluid Shell → Adaptive Workspace → Locally Constrained Content”; canonical localhost is the visual reference.

**Account-audit source caveat found during this handoff audit:** `actions/users/update_user.php` commits the account change and any role-change session revocation before it calls `logAudit()`, and does not check that function's boolean result. `auth/session_guard.php` checks the database role and active session on protected requests, so this observation alone does not show continued old-role access. It does mean account edits cannot be described as audit-atomic from source alone. Confirm the intended audit requirement and test a failed audit write in isolated QA before classifying or correcting this path; no such failure test was run for this documentation audit.

## Deployment and recovery boundary

The local XAMPP database and any hosted installation are separate. Never infer hosted PHP extensions, writable paths, GD/camera support, scheduler, or database state from local success. `config/environment.php` and any credentials must be provisioned through a secure channel and never pasted into an account prompt or migration package. The same applies to database dumps, private storage, audit/Student records and backups. See `docs/APRISM_MIGRATION_PACKAGE_MANIFEST.md` for a transfer/exclusion checklist. Before any deployment: preserve a verified restorable backup, inspect hosted configuration/schema/ledger, plan rollback, run migrations only with explicit authorization, and perform bounded role/device verification. This handoff authorizes none of those actions.
